# 复现：How much can language models memorize?

复现对象：Morris 等，*How much can language models memorize?*，ICML 2026（PMLR 306）。

这里只复现了论文**第 2.3 节的度量方法**和**第 3 节的容量实验**，第 4、5 节（真实文本上的双下降、成员推断）没有做。

## 做了什么

论文把"模型记住了多少"换算成"能压缩掉多少比特"：模型对一条数据越有把握，编码它所需的比特越少。

对一条序列，编码长度是 `−Σ log₂ p(xₜ | x_<t)`。随机数据每条的信息量是固定的（V=2048、S=64 时为 693 比特），所以：

```
记住的比特 = 693 − 模型编码这条数据的比特
```

三步：

1. **写度量 + 校准**（`step1_sanity.py`）：先用小配置验证函数是否正确
2. **测容量**（`step2_sweep.py`）：每个数据量从零训练一个新模型，看总记忆量何时饱和
3. **两个对照**（`check_40k.py`、`check_tied.py`）：排除训练不足，并检查参数统计口径

## 文件

```
memlib.py        模型、造数据、记忆量计算
step1_sanity.py  度量正确性的校准
step2_sweep.py   容量扫描（主实验）
check_40k.py     单点：把训练步数加倍，看容量是否还涨
check_tied.py    对照：输出层与词嵌入共享参数
out/             结果（sweep.csv / sweep.png）
```

## 怎么运行

环境：Python + PyTorch（CUDA）。本机用 `D:\python\.venv-mem`。

```bash
python step1_sanity.py     # 几秒
python step2_sweep.py      # 4 个数据量 × 20000 步，约 26 分钟
python check_40k.py        # 单点 40000 步，约 13 分钟
python check_tied.py       # 同上，改成共享参数
```

## 结果

| 数据量 | 每条剩余编码 | 总记忆（bits） | bit/参数 | 占理论最大值 |
|---|---|---|---|---|
| 1024 | 0.47 | 709,151 | 0.76 | 99.9% |
| 2048 | 0.87 | 1,417,481 | 1.53 | 99.9% |
| 4096 | 148.16 | 2,231,664 | 2.40 | 78.6% |
| 8192 | 426.88 | 2,180,087 | 2.35 | 38.4% |

- 数据量翻倍（4096 → 8192），总记忆量基本不变 → **容量饱和**
- 8192 那个点训练 40000 步，总记忆只从 218.0 万涨到 229.0 万（+5%），末段 loss 不再下降 → **不是训练不足**
- 权重共享对照：参数量降到 667,136，但总记忆跌到 145.2 万（−37%），比例降到 2.18 → **输出层不是冗余参数**

## 和论文的差距

本实验 **2.46 bit/参数**，论文 3.5–3.6。若不计输入嵌入层（667,136 参数）则为 **3.43**，与论文接近。差异更可能来自参数统计口径、模型尺度（论文最大 2000 万参数，本实验 92.9 万）和训练步数（40,000 vs 10⁶）。

## 局限

- 每次只用一个随机种子，没有取平均
- 模型规模约为论文最大配置的 1/20，数据量网格相应缩小，**曲线形状可比，绝对位置不可直接比**
- 第 4、5 节尚未复现
